# Change contract, L3 cycle 1: trade-lifecycle on duckdb-sqlmesh

- **Prior policy authority:** `chain/l2/trade-lifecycle/semantic-model.json` restricted to `chain/l2/trade-lifecycle/review.json` `selected_element_ids` (use its model_sha256). Upstream `governed.account` comes from the ownership-history projection on this same target; the runner places both jobs' models in one SQLMesh project.
- **Exact active change authority:** none. Initial compilation.
- **Stable projection contracts:** `chain/anchors/DEVELOPER-CONTRACT-L2-L3.md` including the SQLMesh layout section; profile `chain/profiles/duckdb-sqlmesh.json`. Output under `chain/l3/duckdb-sqlmesh/trade-lifecycle/`: `manifest.json`, `models/trade.sql`, `audits/<invariant id>.sql`.
- **Write surface, per the profile:** `logical.trade` is incremental_by_identity and SQLMesh has no native DuckDB MERGE. Use `kind CUSTOM (materialization 'governed_merge', materialization_properties ('unique_key' = 'trade_number', 'mutable_columns' = '<the mutable-role attributes, comma separated>', 'frozen_columns' = '<the frozen-role attributes, comma separated>'))` with `columns (...)` declaring every attribute and its physical type. The runner supplies the materialization; it builds a native MERGE from your SELECT and refuses to run if a frozen column appears among the mutable ones. Your SELECT is the source of incoming reports resolved as the model's selectors say; the materialization handles insert versus update.
- **Selectors:** as in the native contract: first_encounter_only by anchored report_order evaluated for trades not yet present; latest_change from the latest I or U report; as_of_event_time against governed.account by effective_from at or before placed_at; same_statement_as_owning_account_reference; first_seen_late by the anchored status_order. Because a FULL SELECT cannot see the target table, state the frozen values from the trade's first report in the SELECT; the materialization preserves them on match by not updating frozen columns.
- **Forbidden shortcuts / conflict protocol:** unchanged. If the model or profile leaves something the SELECT must decide, file the question.
